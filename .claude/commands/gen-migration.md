---
description: Generate a Drizzle migration from schema changes, review it, then apply it.
---

Migrations are **Drizzle Kit** over `bun:sqlite`. They are generated by diffing
the Drizzle schema (`src/infra/db/schema.ts` barrel) against the last snapshot,
and are **forward-only** (SQLite; there is no `down()`/revert).

The user may pass a name (e.g. `/gen-migration add_bonus`). If given, pass it
through as `--name`; otherwise Drizzle Kit auto-names the file.

Before generating: make sure the schema changes are complete and the table is
**registered in the barrel** `src/infra/db/schema.ts`, with explicitly-named
indexes/unique constraints (`UQ_...`, `..._index`) and FK `onDelete` set —
otherwise the diff is noisy.

## Generate

```
bun run mig:gen                 # drizzle-kit generate (auto-named)
bun run mig:gen --name add_bonus
```

This writes a `.sql` migration + a snapshot `.json` into
`src/infra/db/migrations/` (and its `meta/`). `scripts/build.ts` copies these
into `dist/` so the boot-time migrator finds them.

## Review

Read the generated `.sql` in `src/infra/db/migrations/` and show it to the user.
Verify:

- The statements match the intended change; **no unexpected `DROP` / data-loss**
  (Drizzle Kit may prompt on ambiguous renames — resolve deliberately).
- Constraint/index names match the schema (`UQ_...`, `..._index`) — Drizzle
  emits the names you declared in `sqliteTable(...)`.
- Timestamp columns are `integer` (epoch-ms), booleans `integer` — that's the
  `columns.ts` convention, not Postgres `timestamptz`.

## Apply

```
bun run mig:run                 # drizzle-kit migrate — apply pending
```

Migrations also **auto-apply on app boot** (`createDrizzleClient()` runs
`migrate()`), so a fresh SQLite file is always schema-current — `mig:run` is for
applying against an existing file without booting.

For rapid local iteration you can skip migration files entirely with
`bun run db:push` (drizzle-kit push — dev only). There is **no** revert command
(forward-only); to undo in dev, delete the SQLite file (or the migration + its
snapshot entry) and regenerate. Inspect data with `bun run db:studio`.
